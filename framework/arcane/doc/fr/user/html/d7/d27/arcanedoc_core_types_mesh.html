Le maillage

L'interface IMesh (définie dans arcane/core/IMesh.h) est l'interface d'un maillage. Un maillage est composé d'un ensemble d'entités (Item), telles que des nœuds (Node), des arêtes (Edge), des faces (Face) ou des mailles (Cell). Il est également possible d'associer d'autres types d'entités, tels que des particules (Particle) ou des degrés de liberté (DoF).

Les entités du même type sont gérées dans une famille (IItemFamily, voir La famille d'entités). Un maillage a une dimension, récupérable via IMesh::dimension(), qui peut être 1, 2 ou 3. La dimension correspond à la dimension des éléments de maille.

Lorsqu'une application Arcane s'exécute en parallèle, le maillage est partitionné en plusieurs sous-domaines : chaque sous-domaine possède une partie du maillage, complétée par une ou plusieurs couches d' entités fantômes appartenant aux autres sous-domaines (voir Prise en compte du parallélisme dans Arcane). L'instance IMesh d'un sous-domaine représente cette vue locale du maillage.

Maillages primaires et secondaires

Il existe deux types de maillages implémentant IMesh :

  • les maillages primaires, qui implémentent également l'interface IPrimaryMesh et qui peuvent être créés dynamiquement ou en lisant un fichier. Un maillage primaire est créé soit lors de la lecture du jeu de données, soit par programmation, en appelant l'une des méthodes IMainFactory::createMesh(). Il n'est pas possible de supprimer un maillage primaire.
  • les maillages secondaires (également appelés sous-maillages), qui dépendent d'un maillage primaire et représentent un sous-ensemble de celui-ci. Un sous-maillage est attaché à son parent via IMesh::defineParentForBuild(), et la relation parent/enfant peut être récupérée avec IMesh::parentMesh() / IMesh::parentGroup() et IMesh::childMeshes().

IMesh::isPrimaryMesh() indique si l'instance est un maillage primaire, et IMesh::toPrimaryMesh() retourne l'instance sous la forme d'un IPrimaryMesh (en lançant une exception si ce n'est pas le cas).

Obtenir un maillage

Le maillage par défaut d'un sous-domaine est récupéré avec ISubDomain::defaultMesh(). Il est généralement préférable d'utiliser ISubDomain::defaultMeshHandle(), qui retourne un MeshHandle : une référence stable au maillage qui existe toujours, même si le maillage associé n'a pas encore été créé.

Un sous-domaine peut avoir plusieurs maillages. Ils sont gérés par le gestionnaire de maillage, récupéré avec ISubDomain::meshMng(), et la liste des maillages est disponible via ISubDomain::meshes().

Entités et familles de maillage

Pour tout maillage, il existe exactement une famille de nœuds, une d'arêtes, une de faces et une de mailles. Ces entités sont appelées entités de base du maillage et les familles associées sont les familles de base du maillage :

  • IMesh::nodeFamily(), IMesh::edgeFamily(), IMesh::faceFamily(), IMesh::cellFamily()

Selon l'implémentation et la connectivité demandée, une famille peut ne contenir aucun élément. Par exemple, par défaut en 3D, les arêtes ne sont pas créées.

Il est également possible de créer des familles supplémentaires pour d'autres types d'entités ou des familles nommées :

IMesh* mesh = subDomain()->defaultMesh();
IItemFamily* particles = mesh->createItemFamily(IK_Particle, "MyParticles");
IItemFamily* family = mesh->findItemFamily(IK_Particle, "MyParticles");

Le nombre d'entités de chaque type de base est donné par IMesh::nbNode(), IMesh::nbEdge(), IMesh::nbFace() et IMesh::nbCell() (ou IMesh::nbItem() pour un type générique).

Les types de maille suivent la convention de numérotation de la bibliothèque VTK (voir Les types de mailles).

Groupes d'entités

Un groupe d'entités (ItemGroup) contient un ensemble d'entités d'une famille donnée. Les groupes sont la principale façon d'itérer sur les entités d'un maillage. L'interface IMesh fournit les groupes intégrés suivants :

Groupe Description
IMesh::allNodes() / IMesh::allEdges() / IMesh::allFaces() / IMesh::allCells() Toutes les entités du sous-domaine (y compris les fantômes)
IMesh::ownNodes() / IMesh::ownEdges() / IMesh::ownFaces() / IMesh::ownCells() Entités possédées par le sous-domaine
IMesh::outerFaces() Faces sur la frontière du sous-domaine

D'autres groupes peuvent être créés et recherchés par nom :

  • IMesh::groups(): la collection de tous les groupes,
  • IMesh::findGroup(): le groupe nommé name, ou un groupe nul s'il n'existe pas,
  • IMesh::destroyGroups(): détruit tous les groupes.

Les groupes sont la méthode recommandée pour conserver un ensemble d'entités lors des modifications du maillage : les instances d'entités (Item) et leurs identifiants locaux peuvent devenir invalides après une mise à jour du maillage, tandis que les groupes sont mis à jour automatiquement.

Modifier un maillage

Un maillage peut être dynamique, c'est-à-dire capable d'évoluer pendant le calcul (IMesh::isDynamic()). Les modifications sont effectuées via l'interface IMeshModifier, récupérée avec IMesh::modifier() :

IMesh* mesh = subDomain()->defaultMesh();
IMeshModifier* mod = mesh->modifier();
mod->addCells(0, cells_infos, true); // ajoute les mailles décrites par des numéros uniques
mod->removeCells(cells_to_remove); // supprime les mailles (par identifiant local)
mod->endUpdate(); // collectif : finalise la modification

Une fois les modifications effectuées, IMeshModifier::endUpdate() doit être appelé. Cette méthode est collective et, en fonction des propriétés du maillage (voir ci-dessous), trie et/ou compacte les entités, met à jour les groupes, redimensionne les variables et met à jour les couches fantômes.

Avertissement
Le tri ou la compaction des entités modifie le Arcane::Item::localId () "Item::localId ()" de toutes les entités géométriques du maillage. Par conséquent, il ne faut pas conserver une entité via la classe Item (ou une classe dérivée) ou son identifiant local après avoir appelé cette méthode. Il faut utiliser des groupes (ou des numéros uniques) à la place.

Créer un maillage primaire par programmation

Pour créer un maillage 2D vide nommé "Mesh2" :

// sd est le sous-domaine actuel.
ISubDomain* sd = ...;
IParallelMng* pm = sd->parallelMng();
IMainFactory* mf = sd->application()->mainFactory();
IPrimaryMesh* new_mesh = mf->createMesh(sd, pm, "Mesh2");
new_mesh->setDimension(2);
new_mesh->allocateCells(0, Int64ConstArrayView(), false);
new_mesh->endAllocate();

Le maillage créé existe sur tous les rangs de l'IParallelMng passé en argument. Pour créer un maillage sur un seul processeur, il est possible d'utiliser IParallelMng::sequentialParallelMng(). La dimension du maillage doit être définie avec IPrimaryMesh::setDimension() avant d'allouer des mailles.

Il est également possible de lire un maillage directement à partir d'un fichier en utilisant la classe MeshReaderMng. Le lecteur utilisé est sélectionné en fonction de l'extension du nom de fichier, et le maillage est créé par l'appel :

// sd est le sous-domaine actuel.
MeshReaderMng mrm(sd);
IMesh* mesh = mrm.readMesh("Mesh2", "sod.vtk");
// Pour lire le maillage sur un groupe spécifique de sous-domaines :
IMesh* mesh3 = mrm.readMesh("Mesh3", "sod.vtk", sd->parallelMng());

Propriétés du maillage

Un maillage possède des propriétés, accessibles via Arcane::IMesh::properties () "IMesh::properties ()" :

  • "sort" (booléen, vrai par défaut) : les entités doivent être triées par numéro unique croissant après une modification du maillage. Cela garantit que les opérations se déroulent toujours dans le même ordre parallèle, quel que soit le nombre de sous-domaines.
  • "compact" (booléen, vrai par défaut) : les entités doivent être compactées après une modification du maillage, afin qu'il n'y ait pas de lacunes dans la numérotation locale (les identifiants locaux sont renumérotés de 0 au nombre d'entités). La compaction est une opération coûteuse car elle nécessite la mise à jour de toutes les variables.
  • "dump" (booléen, vrai par défaut) : le maillage doit être sauvegardé lors d'une protection.
  • "edges" (booléen, faux par défaut) : les arêtes doivent être créées dans un maillage 3D.
  • "sort-subitemitem-group" (booléen, faux par défaut) : indique si les groupes d'entités connectées créés dynamiquement (par exemple, allCells().nodes()) sont triés. Doit être défini lors de la création du maillage.

Équilibrage de charge et redistribution

Lorsque l'équilibrage de charge redistribue le maillage entre les processeurs, la variable IPrimaryMesh::itemsNewOwner() du maillage primaire contient, pour chaque entité, le numéro de son nouveau sous-domaine propriétaire. Ces variables doivent être synchronisées, et la redistribution est ensuite effectuée avec IPrimaryMesh::exchangeItems() :

  • le sous-domaine donne aux autres sous-domaines les mailles qui leur appartiennent désormais, et reçoit les nouvelles mailles (et de même pour les nœuds, les arêtes et les faces),
  • les valeurs des variables et des groupes d'entités sont échangées,
  • la méthode déclenche un appel implicite à IMeshModifier::endUpdate().

Après l'appel, il peut être nécessaire d'exécuter les points d'entrée de changement de maillage (Arcane::ITimeLoopMng:: execOnMeshChangedEntryPoints() "ITimeLoopMng:: execOnMeshChangedEntryPoints()").

Autres fonctionnalités

  • AMR : si l'affinement adaptatif du maillage est activé (IMesh::isAmrActivated()), le maillage fournit les groupes de mailles actives (IMesh::allActiveCells(), IMesh::ownActiveCells()) et les mailles à un niveau donné (IMesh::allLevelCells()). Voir AMR pour les maillages cartésiens.
  • Couches fantômes : IMesh::ghostLayerMng() donne accès au gestionnaire de couches fantômes et IMesh::updateGhostLayers() reconstruit les couches fantômes.
  • Connectivité : IMesh::connectivity() retourne le descripteur de connectivité (un VariableScalarInteger utilisant la numérotation de connectivité Arcane, voir Gestion des connectivités des entités), et IMesh::indexedConnectivityMng() le gestionnaire de connectivité incrémentale indexée.
  • Numéros uniques : IMesh::meshUniqueIdMng() gère la numérotation unique des entités.
  • Interfaces semi-conformes : IMesh::computeTiedInterfaces(), IMesh::hasTiedInterface() et IMesh::tiedInterfaces() gèrent les interfaces liées entre sous-maillages non conformes.
  • Contraintes de partitionnement : IMesh::partitionConstraintMng() gère les contraintes sur le partitionnement du maillage.
  • Utilitaires et vérifications : IMesh::utilities() donne accès aux fonctions utilitaires du maillage (IMeshUtilities), IMesh::checker() au vérificateur de validité du maillage, IMesh::checkValidMesh() (local) et IMesh::checkValidMeshFull() (collectif, sur tous les sous-domaines) pour valider les structures internes.
  • Événements : IMesh::eventObservable() fournit des observables pour les événements du maillage.
  • Données utilisateur : IMesh::userDataList() permet d'associer des données utilisateur au maillage.
  • Réseau de familles : IMesh::itemFamilyNetwork() donne accès au graphe des familles connectées.

Points clés

  • IMesh est la vue locale (par sous-domaine) d'un maillage : il contient les entités possédées par le sous-domaine plus les entités fantômes.
  • Utiliser ISubDomain::defaultMeshHandle() (un MeshHandle) plutôt que ISubDomain::defaultMesh() lorsque le maillage n'a peut-être pas encore été créé.
  • Les maillages primaires sont créés par le jeu de données ou via IMainFactory::createMesh() ; les sous-maillages sont des sous-ensembles d'un maillage primaire.
  • Modifier le maillage uniquement via IMesh::modifier(), et toujours appeler IMeshModifier::endUpdate() après une modification.
  • Ne pas conserver les instances Item ou les valeurs Item::localId() à travers un IMeshModifier::endUpdate() : utiliser des groupes ou des numéros uniques.
