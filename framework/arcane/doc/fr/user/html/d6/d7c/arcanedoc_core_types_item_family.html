La famille d'entités

L'interface IItemFamily (définie dans arcane/core/IItemFamily.h) est l'interface d'une famille d'entités. Une famille gère toutes les entités du même type (Item::kind()) et est attachée à un maillage (IMesh, voir Le maillage).

Pour tout maillage, il existe exactement une famille de nœuds (Node), une d'arêtes (Edge), une de faces (Face) et une de mailles (Cell). Ces entités sont appelées entités de maillage de base et les familles associées sont les familles de maillage de base.

Selon l'implémentation, il peut également y avoir des familles de particules (Particle), de nœuds duals, de liens ou de degrés de liberté (DoF). Selon la connectivité demandée, une famille peut ne pas avoir d'éléments. Par exemple, par défaut en 3D, les arêtes ne sont pas créées.

Les types d'entités sont définis par l'énumération eItemKind : IK_Node, IK_Edge, IK_Face, IK_Cell, IK_DoF, IK_Particle.

Obtenir une famille

Les familles d'un maillage sont récupérées à partir de l'interface IMesh :

  • IMesh::nodeFamily(), IMesh::edgeFamily(), IMesh::faceFamily(), IMesh::cellFamily(): les familles de base,
  • IMesh::itemFamily(): la famille du type de base kind,
  • IMesh::findItemFamily(): la famille nommée name (lève une exception si elle n'existe pas),
  • IMesh::createItemFamily(): crée une nouvelle famille,
  • IMesh::itemFamilies(): la collection de toutes les familles du maillage.

Une famille fournit son nom (IItemFamily::name(), et IItemFamily::fullName() qui inclut le nom du maillage), son type (IItemFamily::itemKind()), et ses objets associés : IItemFamily::mesh(), IItemFamily::parallelMng(), IItemFamily::traceMng(), IItemFamily::policyMng() (le gestionnaire de comportements/politiques), et IItemFamily::properties().

Identifiants d'entités

Chaque entité dans une famille possède deux identifiants :

  • l' identifiant local, Item::localId() : la position de l'entité au sein de la famille du sous-domaine local. Cet identifiant peut être modifié lorsque la famille évolue (ajout, suppression ou compaction d'entités), et les identifiants locaux ne sont pas nécessairement contigus. IItemFamily::nbItem() donne le nombre d'entités et IItemFamily::maxLocalId() le maximum d'identifiant local (qui est la taille requise pour dimensionner les variables sur la famille).
  • l' identifiant unique, Item::uniqueId() : stable tout au long du calcul et unique dans tous les sous-domaines. C'est l'identifiant à utiliser pour faire référence à une entité d'un sous-domaine à un autre.

Par défaut, une famille possède une table de conversion de Item::uniqueId() vers Item::localId(). Cette table doit exister pour permettre :

  • la garantie que le numéro unique est unique au sein du sous-domaine et dans tous les sous-domaines,
  • les méthodes de conversion IItemFamily::itemsUniqueIdToLocalId(),
  • la présence des entités de la famille dans plusieurs sous-domaines,
  • les synchronisations,
  • les variables partielles sur la famille.

Il est possible d'activer ou de désactiver cette table de conversion avec IItemFamily::setHasUniqueIdMap() (et de la consulter avec IItemFamily::hasUniqueIdMap()), mais uniquement si aucune entité n'a été créée, et pas sur les familles de nœuds, d'arêtes, de faces et de mailles.

Pour convertir les numéros uniques en numéros locaux :

IItemFamily* family = mesh->cellFamily();
Int32Array local_ids(nb_unique);
family->itemsUniqueIdToLocalId(local_ids, unique_ids, true);
// local_ids[i] est l'identifiant local de l'entité avec le numéro unique
// unique_ids[i], ou NULL_ITEM_ID si non trouvé (et une erreur fatale si
// do_fatal est vrai).
Avertissement
Lorsque la famille est modifiée par l'ajout ou la suppression d'entités, les variables et les groupes qui dépendent de cette famille ne sont plus utilisables tant que IItemFamily::endUpdate() n'est pas appelé, et les instances d'entités (Item) sont invalidées. Pour conserver une référence à une entité, il faut soit utiliser un groupe (ItemGroup), soit conserver son numéro unique et utiliser IItemFamily::itemsUniqueIdToLocalId().

Groupes et variables sur la famille

Une famille gère les groupes et les variables de ses entités :

  • IItemFamily::allItems(): le groupe de toutes les entités de la famille,
  • IItemFamily::groups(): la collection de groupes dans la famille,
  • IItemFamily::findGroup(): recherche un groupe (par nom, en le créant si nécessaire),
  • IItemFamily::createGroup(): crée un groupe,
  • IItemFamily::destroyGroups(): supprime tous les groupes de la famille,
  • IItemFamily::findVariable(): recherche la variable nommée name associée à la famille,
  • IItemFamily::usedVariables(): ajoute la liste des variables utilisées par la famille à une collection.

Les variables définies sur les entités de la famille (telles que les variables déclarées par AXL d'un module sur la famille de mailles) sont redimensionnées automatiquement lorsque la famille est mise à jour.

Modifier la liste d'entités

Après avoir modifié la liste d'entités (ajout ou suppression d'entités), il faut appeler IItemFamily::endUpdate(). Cela met à jour les groupes et redimensionne les variables sur la famille.

À des fins d'optimisation, lors de l'exécution de plusieurs modifications successives, il est possible d'utiliser les méthodes de mise à jour partielle (réservées aux utilisateurs expérimentés) :

  • IItemFamily::partialEndUpdate(): met à jour les structures internes sans mettre à jour les groupes ou les variables. Seul le groupe allItems() est disponible.
  • IItemFamily::partialEndUpdateGroup(): met à jour un seul groupe après la modification (supprime les entités qui ont été détruites).
  • IItemFamily::partialEndUpdateVariable(): redimensionne une seule variable après la modification.

Autres méthodes liées à la modification :

  • IItemFamily::clearItems(): supprime toutes les entités de la famille (attention à ne pas détruire des entités utilisées par une autre famille ; il est généralement plus sûr d'utiliser IMeshModifier::clearItems() pour supprimer tous les éléments du maillage),
  • IItemFamily::compactItems(): compresse les entités afin que les identifiants locaux soient renumérotés de 0 à nbItem()-1,
  • IItemFamily::setItemSortFunction() / IItemFamily::itemSortFunction(): définit la fonction de tri des entités (par défaut, les entités sont triées par numéro unique croissant),
  • IItemFamily::notifyItemsOwnerChanged(): notifie que les entités possédées par le sous-domaine ont changé,
  • IItemFamily::notifyItemsUniqueIdChanged(): notifie que les identifiants uniques des entités ont changé,
  • IItemFamily::addGhostItems(): alloue des entités fantômes (les entités présentes sur un autre sous-domaine) ; IItemFamily::endUpdate() doit être appelé après les allocations,
  • IItemFamily::copyItemsValues() / IItemFamily::copyItemsMeanValues(): copie (ou moyenne) les valeurs des entités d'une liste dans les entités d'une autre liste,
  • IItemFamily::experimentalChangeUniqueId(): change le numéro unique d'une entité (expérimental : uniquement pour les entités non encore connectées à d'autres).

Synchronisation et entités fantômes

En parallèle, les entités d'une famille peuvent être partagées par plusieurs sous-domaines (entités fantômes). La synchronisation des variables entre les sous-domaines est gérée par la famille :

  • IItemFamily::computeSynchronizeInfos(): construit les structures nécessaires à la synchronisation. Cette opération collective doit être effectuée chaque fois que les entités changent de propriétaire (par exemple, lors d'un équilibrage de charge),
  • IItemFamily::synchronize(): synchronise les variables données (qui doivent provenir de cette famille et ne doivent pas être partielles) sur toutes les entités de la famille, ou sur une liste d'entités,
  • IItemFamily::allItemsSynchronizer(): le synchroniseur sur toutes les entités de la famille,
  • IItemFamily::reduceFromGhostItems(): applique une opération de réduction à partir des entités fantômes (l'inverse d'une synchronisation),
  • IItemFamily::getCommunicatingSubDomains(): la liste des sous-domaines qui communiquent pour les entités,
  • IItemFamily::itemsNewOwner(): la variable contenant le numéro du nouveau sous-domaine propriétaire des entités (utilisée pour le partitionnement du maillage).

Voir Prise en compte du parallélisme dans Arcane pour une présentation générale de la synchronisation dans Arcane.

Adjacences et connectivité

La famille fournit des méthodes pour calculer les listes d'adjacence :

  • IItemFamily::findAdjacencyItems(): recherche la liste des entités d'un sous-type donné, liées par un type de lien donné, sur un certain nombre de couches. Si la liste n'existe pas, elle est créée.
  • IItemFamily::localConnectivityInfos() / IItemFamily::globalConnectivityInfos(): les informations sur la connectivité, locale au sous-domaine ou globale sur tous les sous-domaines.

La connectivité entre les entités du maillage est décrite par le mécanisme de connectivité présenté dans Gestion des connectivités des entités.

Imbrication de sous-maillages

Un sous-maillage (voir Maillages primaires et secondaires) possède des familles imbriquées par rapport aux familles de son maillage parent :

  • IItemFamily::parentFamily(): la famille parente (ou nullptr),
  • IItemFamily::childFamilies(): les familles enfants,
  • IItemFamily::parentFamilyDepth(): la profondeur d'imbrication de la famille actuelle,
  • IItemFamily::setParentFamily() / IItemFamily::addChildFamily(): configure l'imbrication (à utiliser avant IItemFamily::build() pour les sous-maillages construits dynamiquement).

Autres fonctionnalités

  • IItemFamily::view(): une vue sur les entités de la famille (valide uniquement tant que la famille n'évolue pas),
  • IItemFamily::toParticleFamily() / IItemFamily::toDoFFamily(): convertit la famille en l'interface IParticleFamily ou IDoFFamily lorsque le type correspond,
  • IItemFamily::checkValid() / IItemFamily::checkValidConnectivity(): vérifie la validité des structures internes,
  • IItemFamily::checkUniqueIds(): vérifie collectivement que les identifiants uniques donnés sont réellement uniques pour tous les sous-domaines,
  • IItemFamily::itemListChangedEvent(): un événement notifié lorsque des entités sont ajoutées ou supprimées,
  • IItemFamily::prepareForDump() / IItemFamily::readFromDump(): prépare ou lit les données de la famille pour un dump.

Points clés

  • Une famille est le conteneur par maillage de toutes les entités d'un même type : elle possède leur numérotation, leurs groupes, leurs variables et leur synchronisation.
  • Le Item::localId() d'une entité peut changer lorsque la famille évolue ; le Item::uniqueId() est stable. Il faut utiliser le numéro unique (et IItemFamily::itemsUniqueIdToLocalId()) pour faire référence à une entité à travers les modifications ou à travers les sous-domaines.
  • Après toute modification de la liste d'entités, il faut appeler IItemFamily::endUpdate() (ou les méthodes de mise à jour partielle) avant de réutiliser les groupes et les variables.
  • Pour les familles de maillage de base (nœud, arête, face, maille), la table de conversion unique vers local est obligatoire ; pour les autres familles, elle peut être désactivée avant que toute entité ne soit créée.
