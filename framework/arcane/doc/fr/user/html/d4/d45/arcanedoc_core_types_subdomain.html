Le sous-domaine

L'interface ISubDomain (définie dans arcane/core/ISubDomain.h) est l'interface du gestionnaire de sous-domaine. C'est l'objet central représentant l'état local et l'environnement d'exécution d'une seule unité de calcul d'une application Arcane.

Qu'est-ce qu'un sous-domaine ?

Lorsqu'une application Arcane s'exécute en parallèle, le maillage global est partitionné en plusieurs sous-domaines : chaque unité de calcul (un rang MPI, éventuellement associée à un ensemble de threads) possède une portion du maillage ainsi que les variables locales, les modules, les services et les options de cas qui y sont associées. L'instance ISubDomain est le handle vers cette portion locale de l'application.

La hiérarchie des objets est la suivante :

IApplication (une par exécutable)
└── ISession (une par session de calcul)
└── ISubDomain (une par unité (rang, thread))
├── IVariableMng, IModuleMng, IEntryPointMng, IServiceMng, ...
├── IMeshMng → IMesh (maillage par défaut)
├── ICaseMng (le jeu de données .arc)
└── ...
  • IApplication est le gestionnaire au niveau du processus : il est partagé par tous les sous-domaines du processus (usine principale, informations d'application, gestionnaire de ressources, ...).
  • ISession regroupe un ou plusieurs sous-domaines. Dans la réplication de domaine (plusieurs calculs indépendants partageant les mêmes processus), une session contient plusieurs instances ISubDomain, une par réplique.
  • ISubDomain est l'endroit où réside l'identité de l'unité de calcul : ISubDomain::subDomainId() est le rang dans le groupe parallèle du sous-domaine et ISubDomain::nbSubDomain() est la taille de ce groupe.

En réplication de domaine, ISubDomain::parallelMng() couvre uniquement le groupe parallèle d'une réplique, tandis que ISubDomain::allReplicaParallelMng() couvre le groupe de toutes les répliques. Sans réplication, les deux gestionnaires sont identiques.

Accès aux gestionnaires principaux

La plupart de l'interface ISubDomain est constituée d'accesseurs vers les gestionnaires appartenant au sous-domaine. Ils sont regroupés ici par catégorie :

Catégorie Accesseurs
Données ISubDomain::variableMng() (toutes les instances IVariable), ISubDomain::meshMng() et ISubDomain::defaultMesh() / ISubDomain::defaultMeshHandle() / ISubDomain::meshes(), ISubDomain::propertyMng()
Structure ISubDomain::moduleMng(), ISubDomain::entryPointMng(), ISubDomain::moduleMaster() (le module maître, toujours créé)
Parallélisme / threads ISubDomain::parallelMng(), ISubDomain::allReplicaParallelMng(), ISubDomain::threadMng(), ISubDomain::timerMng(), ISubDomain::timeStats(), ISubDomain::loadBalanceMng()
Temps ISubDomain::timeLoopMng(), ISubDomain::timeHistoryMng()
E/S et fichier de cas ISubDomain::ioMng(), ISubDomain::caseMng() (le ICaseMng du jeu de données), ISubDomain::caseDocument(), ISubDomain::caseOptionsMain(), ISubDomain::commonVariables()
Protection ISubDomain::checkpointMng()
Autres ISubDomain::acceleratorMng(), ISubDomain::memoryInfo(), ISubDomain::physicalUnitSystem(), ISubDomain::configuration(), ISubDomain::mainFactory(), ISubDomain::session(), ISubDomain::application(), ISubDomain::applicationInfo()

ISubDomain est donc l'endroit où chercher tout ce qui est « à moi » dans l'application : mes variables, mon maillage, mon groupe parallèle, mes options de cas. Pour une description détaillée du maillage et des familles d'entités qu'il contient, voir Le maillage et La famille d'entités.

Méthodes liées au maillage

Le sous-domaine gère les maillages associés à l'unité de calcul. Les méthodes principales sont :

  • ISubDomain::defaultMesh() / ISubDomain::defaultMeshHandle(): le maillage par défaut du sous-domaine (nommé "Mesh0"). Le handle existe toujours, même si le maillage associé n'a pas encore été créé.
  • ISubDomain::meshes(): la liste de tous les maillages du sous-domaine.
  • ISubDomain::allocateMeshes(): alloue les instances IMesh (elles sont créées mais ne contiennent aucune entité). Cette méthode doit être appelée avant toute autre opération impliquant le maillage.
  • ISubDomain::readOrReloadMeshes(): lit les maillages. Au démarrage, les maillages sont lus à partir du jeu de données ; lors d'un redémarrage, ils sont chargés à partir d'une protection.
  • ISubDomain::initializeMeshVariablesFromCaseFile(): initialise les variables dont les valeurs sont spécifiées dans le jeu de données.
  • ISubDomain::doInitMeshPartition(): applique le partitionnement initial du maillage (voir Prise en compte du parallélisme dans Arcane).
  • ISubDomain::setInitialPartitioner(): définit le partitionneur à utiliser pour le partitionnement initial. Le sous-domaine prend possession de l'instance et la détruit à la fin du calcul. Cette méthode doit être appelée avant l'initialisation du module, par exemple dans un point d'entrée de construction.
Avertissement
Les méthodes ISubDomain::mesh(), findMesh(), addMesh() et ISubDomain::meshDimension() sont obsolètes. Il faut utiliser à la place Arcane::ISubDomain:: defaultMeshHandle() "ISubDomain:: defaultMeshHandle()", IMeshMng::findMeshHandle(), IMeshMng::meshFactoryMng() et IMesh::dimension().

Fichier de cas et répertoires

Le sous-domaine suit le jeu de données (le fichier .arc) et les répertoires de sortie :

  • ISubDomain::caseName(), ISubDomain::caseFullFileName(), ISubDomain::fillCaseBytes(), ISubDomain::setCaseName(): informations sur le jeu de données. ISubDomain::setCaseName() doit être appelé avant l'initialisation.
  • ISubDomain::caseDocument(): le document XML du jeu de données.
  • ISubDomain::caseOptionsMain(): les options globales du jeu de données (CaseOptionsMain).
  • ISubDomain::commonVariables(): les variables « standard » (temps, pas de temps, ...).

Trois répertoires de sortie peuvent être définis (les répertoires doivent exister et les méthodes doivent être appelées avant l'initialisation) :

  • ISubDomain::exportDirectory() / ISubDomain::setExportDirectory(): le répertoire de base pour les exports (protections et redémarrages).
  • ISubDomain::storageDirectory() / ISubDomain::setStorageDirectory(): le répertoire de base pour les exports nécessitant un archivage. S'il n'est pas défini, ISubDomain::exportDirectory() est utilisé.
  • ISubDomain::listingDirectory() / ISubDomain::setListingDirectory(): le répertoire de base pour les listages (logs, informations d'exécution).

Création et cycle de vie

Un sous-domaine est créé à partir d'un objet SubDomainBuildInfo, qui fournit :

  • le gestionnaire parallèle du sous-domaine (SubDomainBuildInfo::parallelMng()),
  • l'index du sous-domaine dans la session (SubDomainBuildInfo::index()),
  • le jeu de données : nom de fichier (informatif) et contenu (SubDomainBuildInfo::caseBytes()),
  • éventuellement, le gestionnaire parallèle de toutes les répliques (SubDomainBuildInfo::allReplicaParallelMng()) pour la réplication de domaine.

La création passe par ISession::createSubDomain() :

SubDomainBuildInfo sdbi(parallel_mng, index);
sdbi.setCaseFileName(case_file_name);
ISubDomain* sub_domain = session->createSubDomain(sdbi);

Le cycle de vie typique d'un sous-domaine est :

Phase Méthodes Description
Build (interne) Création de tous les gestionnaires de sous-domaine (gestionnaire de variables, gestionnaire de modules, gestionnaire de point d'entrée, gestionnaire de services, gestionnaire de cas, gestionnaire de protection, gestionnaire de boucle en temps, ...) et du handle de maillage par défaut.
Initialize (interne) Initialisation de l'accélérateur, lecture du jeu de données (validation du XML et fusion de la configuration), création du maillage par défaut, chargement des services du sous-domaine, création du module maître.
Configuration du maillage ISubDomain::allocateMeshes(), ISubDomain::readOrReloadMeshes(), ISubDomain::initializeMeshVariablesFromCaseFile(), ISubDomain::doInitMeshPartition() Allocation et lecture des maillages, initialisation des variables de maillage à partir du jeu de données, application du partitionnement initial.
Support de redémarrage ISubDomain::setIsContinue() / ISubDomain::isContinue() Indicateur signalant qu'un redémarrage est en cours. ISubDomain::setIsContinue() doit être appelé avant ISubDomain::allocateMeshes() afin que les maillages soient chargés à partir d'une protection au lieu du jeu de données.
Run (code d'application) Les points d'entrée de l'application sont exécutés à travers la boucle en temps.
Destroy ISubDomain::doExitModules(), ISubDomain::destroy() Exécution des points d'entrée de sortie, puis destruction de tous les objets du sous-domaine (le gestionnaire de variables est détruit en dernier, car chaque objet peut contenir des variables).

ISubDomain::isInitialized() / ISubDomain::setIsInitialized() indiquent si le sous-domaine a été initialisé. ISubDomain::onDestroyObservable() permet d'enregistrer une notification qui est appelée avant que le sous-domaine ne soit détruit.

Obtenir le sous-domaine à partir du code

Presque chaque objet appartenant au sous-domaine fournit un accesseur subDomain() pour remonter jusqu'à lui :

  • services : subDomain() hérité de la classe de base de service,
  • modules : IModule::subDomain() hérité de IModule,
  • points d'entrée : IEntryPoint::subDomain() hérité de IEntryPoint,
  • maillages : IMesh::subDomain(),
  • variables : IVariable::subDomain(),
  • familles d'entités : IItemFamily::subDomain(),
  • options de cas : ICaseOptions::subDomain().

Le modèle canonique à l'intérieur d'un point d'entrée ou d'une méthode de service est donc :

void MyModule::onDoSomething()
{
IVariableMng* vpm = subDomain()->variableMng();
IMesh* mesh = subDomain()->defaultMesh();
IParallelMng* pm = subDomain()->parallelMng();
// ...
}

Points clés

  • ISubDomain est l'objet racine par réplique de l'application : tout ce qui a besoin des variables locales, du maillage local, du groupe parallèle local ou des options de cas locales passe par lui.
  • Ce n'est pas l'application : ISubDomain::application() donne les objets à l'échelle du processus. Le sous-domaine est l'endroit où réside l'identité de l'unité de calcul (ISubDomain::subDomainId() est le rang).
  • L'ordre des méthodes d'initialisation est important : ISubDomain::setCaseName(), ISubDomain::setExportDirectory(), ISubDomain::setInitialPartitioner() avant l'initialisation ; ISubDomain::setIsContinue() avant ISubDomain::allocateMeshes().
  • Le sous-domaine est la jonction des modes d'exécution avancés : réplication de domaine (plusieurs sous-domaines par session), redémarrages (protections) et exécution directe (tests), qui se connectent tous via ses setters (ISubDomain::directExecution() / ISubDomain::setDirectExecution()).
