Jeu de données (.ARC)

Introduction

Ce chapître décrit la structure d'un jeu de données. Le jeu de données est un fichier au format XML qui contient les valeurs permettant de paramétrer l'exécution d'un code de calcul.

Voici un exemple de jeu de donnée en anglais :

<?xml version="1.0"?>
<case codename="ArcaneTest" codeversion="1.0">
<arcane>
<title>Tube à choc de Sod</title>
<description>Ce JDD permet de tester le module Hydro simplifié de
Arcane</description>
<timeloop>ArcaneHydroLoop</timeloop>
</arcane>
<!-- Liste des maillages (toujours en anglais) -->
<meshes>
<mesh>
<filename>tube5x5x100.ice</filename>
</mesh>
</meshes>
<functions>
<table name="table-dt" parameter="time" value="real" interpolation="linear">
<value><x>0.0</x><y>1.0e-3</y></value>
<value><x>1.0e-2</x><y>1.0e-5</y></value>
</table>
</functions>
<simple-hydro>
<deltat-init>0.001</deltat-init>
<deltat-min>0.0001</deltat-min>
<deltat-max>0.01</deltat-max>
<final-time>0.2</final-time>
</simple-hydro>
</case>

Un jeu de données se compose de quatre parties :

  • l'élément <arcane> permettant entre autre de configurer la boucle en temps et les modules actifs (voir Élément <arcane>)
  • l'élément maillage (<meshes>) permettant de décrire le maillage (voir Maillages (balise <meshes>)).
  • l'élément contenant les fonctions (<functions> ou <fonctions>)(voir Fonctions (balises <fonctions> ou <functions>))
  • les éléments restants concernent les options des différents modules du code.

Seule la balise <arcane> est requise. Les autres balises sont optionnelles

Avertissement
Les caractères blancs dans les attributs sont interdits dans la norme XML. Le jeu de données est donc invalide s'il y en a. Cependant les analyseurs peuvent les tolérer. Les caractères blancs en début et fin de balises sont significatifs et peuvent changer la signification ou rendre invalide un jeu de données. Par exemple, <file> Toto</file> indique que le fichier de maillage contient un blanc avant les caractères 'Toto'.
Note
Pour des raisons historiques, il est toléré d'avoir des espaces en début ou fin de texte d'une balise dans le cas des options simples du jeu de données (voir Les options simples). Dans ce cas, ces espaces sont ignorés. Par exemple <deltat> 25.0 </deltat> est valide. Ces blancs ne sont autorisés que dans les options des modules et services, pas dans les balises spécifiques à Arcane (comme <arcane>, <functions>, <meshes>, ...).

Élément <arcane>

Cet élément contient les informations sur la boucle en temps utilisée et la liste des modules actifs. Le contenu de cet élément est la première chose lue dans le jeu de données. Les éléments suivants sont possibles :

<arcane>
<title>Tube à choc de Sod</title>
<description>Ce JDD permet de tester le module Hydro simplifié de Arcane</description>
<timeloop>ArcaneHydroLoop</timeloop>
<modules>
<module name="Hydro" actif="true" />
<module name="PostProcessing" actif="false" />
</modules>
<configuration>
<parameter name="NotParallel" value="false" />
<parameter name="NotCheckpoint" value="true" />
</configuration>
</arcane>

Le tableau suivant donne la liste des éléments possibles :

élément anglaisélément francaisdescription
timeloopboucle-en-tempsnom de la boucle en temps utilisée. Ce nom doit correspondre à une boucle en temps disponible dans le fichier de configuration du code.
titletitretitre du jeu de données. Purement informatif.
descriptiondescriptiondescription du cas test. Purement informatif.
modulesmodules

Liste des modules avec leur état d'activation. Cette balise est utilisée pour indiquer si un module optionnel est activé ou non. Par défaut les modules optionnels ne sont pas actifs. Il s'agit d'une liste d'éléments <module> comme suit :

<module name="Module1" active='true' />
<module name="Module2" active='false' />
servicesservices

Liste de services singletons avec leur état d'activation (qui vaut vrai par défaut). Il s'agit d'une liste d'éléments <service> comme suit :

<service name="Service1" active='true' />
<service name="Service2" active='false' />
<service name="Service3" />

Dans l'exemple précédent, les services de nom 'Service1' et 'Service3' seront chargés.

configurationconfiguration

Liste de paramêtres de configuration. Ces paramètres ne sont pas lus par Arcane mais peuvent être utilisés par exemple par la procédure de lancement du code. Chaque paramètre est de la forme suivante :

<parameter name="Param1" value='value1' /> <!-- Anglais -->
<parametre name="Param1" value='value1' /> <!-- Francais -->

Maillages (balise <meshes>)

Il existe deux façons de spécifier les maillages d'un calcul dans un jeu de données :

  • la méthode moderne, basée sur les services de maillage, qui utilise l'élément <meshes>. C'est la méthode recommandée et les nouveaux utilisateurs devraient l'utiliser (voir Spécification des maillages avec les services (balise <meshes>)).
  • la méthode héritée, qui utilise un ou plusieurs éléments <mesh> (ou <maillage> en français). Cette méthode est obsolète et ne doit être utilisée que par les codes existants (voir Spécification héritée des maillages (balise <mesh> ou <maillage>)).
Note
Si les deux méthodes sont utilisées dans le même jeu de données, l'élément <meshes> a la priorité : les maillages sont alors créés par les services de maillage et les éléments <mesh> hérités sont ignorés.

Spécification des maillages avec les services (balise <meshes>)

Avec cette méthode, les maillages sont gérés par des services. L'élément <meshes> est lu par le ArcaneCaseMeshMasterService service. Cet élément est toujours en anglais, même pour un jeu de données français (c'est-à-dire lorsque xml:lang="fr"), car il est lu avant les autres options du jeu de données : les maillages doivent être créés avant que les modules et les services ne soient initialisés, car ces derniers peuvent en avoir besoin.

L'élément <meshes> contient un ou plusieurs éléments <mesh>. Chaque élément <mesh> est une instance d'un service implémentant l'interface Arcane::ICaseMeshService. Par défaut, le ArcaneCaseMeshService service est utilisé et ses options sont décrites dans les sections suivantes (la liste complète et à jour est également disponible dans la page Service 'ArcaneCaseMeshService').

Les maillages sont nommés Mesh0, Mesh1, ... dans l'ordre d'apparition des éléments <mesh>. Le premier maillage (Mesh0) est le maillage par défaut du sous-domaine et doit toujours être créé. Les autres maillages peuvent être nuls sur certains ou tous les sous-domaines (par exemple lorsqu'un service mesh-builder-customiser est utilisé).

Note
Lorsque plusieurs maillages sont définis, un module ou un service peut être associé à un maillage donné en utilisant l'attribut mesh-name de l'élément correspondant du jeu de données (voir Les options de type service).

L'exemple suivant spécifie deux maillages, le premier lu à partir d'un fichier et le second créé par un générateur :

<meshes>
<mesh>
<filename>sod.vtk</filename>
</mesh>
<mesh>
<generator name="Cartesian3D">
<origin>1.0 2.0 3.0</origin>
<x><n>100</n><length>2.0</length></x>
<y><n>15</n><length>2.0</length></y>
<z><n>10</n><length>4.0</length></z>
</generator>
</mesh>
</meshes>

Générateurs de maillage

L'élément <generator> spécifie une implémentation de l'interface Arcane::IMeshBuilder. Le nom du service est donné par l'attribut name. Les générateurs suivants sont fournis par Arcane (la liste des générateurs disponibles dépend des options de compilation) :

Cartesian2D — Générateur de maillage cartésien 2D.

Si la division en X et en Y n'est pas spécifiée, le nombre de sous-domaines doit être un carré parfait (1, 4, 9, 16, 25, ...). Si seule la division en X ou en Y est spécifiée, cette valeur spécifiée doit être un diviseur du nombre de sous-domaines.

ÉlémentTypeValeur par défautDescription
originreal2noneOrigine du maillage.
nb-part-xinteger0Nombre de sous-domaines en X. S'il est absent ou si la valeur 0 est spécifiée, la division en X est calculée dynamiquement.
nb-part-yinteger0Nombre de sous-domaines en Y. S'il est absent ou si la valeur 0 est spécifiée, la division en Y est calculée dynamiquement.
generate-sod-groupsboolfalseSi true, des groupes sont générés pour un cas de test Sod (interne à Arcane).
face-numbering-versioninteger4Version de l'algorithme de numérotation des faces. La version 1 correspond à une numérotation non structurée. La version 4 correspond à une numérotation cartésienne.
xcomplexnoneDescription des blocs de maillage en X (au moins un). Voir ci-dessous.
ycomplexnoneDescription des blocs de maillage en Y (au moins un). Voir ci-dessous.

Cartesian3D — Générateur de maillage cartésien 3D.

Il a les mêmes options que Cartesian2D (avec une origine real3), plus les suivantes :

ÉlémentTypeValeur par défautDescription
nb-part-x / nb-part-y / nb-part-zintegernoneNombre de sous-domaines en X, Y et Z.
edge-numbering-versioninteger2Version de l'algorithme de numérotation des arêtes. Seule la valeur 2 est actuellement valide. Dans ce cas, si les arêtes sont activées, le nombre maximum de nœuds est limité à 2^31.
zcomplexnoneDescription des blocs de maillage en Z (au moins un). Voir ci-dessous.

Pour Cartesian2D et Cartesian3D, le maillage est décrit par des blocs dans chaque direction. Chaque élément <x>, <y> ou <z> décrit un bloc et peut être répété pour décrire plusieurs blocs consécutifs :

<x>
<n>10</n>
<length>2.0</length>
<progression>1.0</progression>
</x>
ÉlémentTypeValeur par défautDescription
nintegernoneNombre de mailles du bloc.
lengthrealnoneLongueur du bloc.
progressionreal1.0Progression géométrique des tailles de maille à l'intérieur du bloc.

Sod3D — Générateur de maillage de tube de choc Sod (3D).

ÉlémentTypeDescription
xintegerNombre de mailles en X.
yintegerNombre de mailles en Y.
zintegerNombre de mailles en Z.

HoneyComb2D — Générateur de maillage hexagonal 2D.

ÉlémentTypeDescription
originreal2Origine du maillage.
pitch-sizerealValeur du pas, qui est la distance entre deux côtés opposés d'un hexagone. Doit être strictement positive.
nb-layerintegerNombre de couches d'hexagones. Si 1, il n'y a que l'hexagone central. Doit être strictement positif.

HoneyComb3D — Générateur de maillage hexagonal 3D.

Il a les mêmes options que HoneyComb2D (l'origine est 2D : les valeurs de hauteur sont fournies par l'option heights), plus la suivante :

ÉlémentTypeDescription
heightsreal[]Liste des hauteurs de maille. Ce tableau doit contenir au moins 2 valeurs. Les valeurs doivent être croissantes. Le nombre de couches de mailles en hauteur est égal au nombre d'éléments dans ce tableau moins 1.

Voici un exemple complet utilisant un générateur :

<meshes>
<mesh>
<generator name="Cartesian2D" >
<nb-part-x>2</nb-part-x>
<nb-part-y>2</nb-part-y>
<origin>0.0 0.0</origin>
<x><n>5</n><length>5.0</length></x>
<y><n>3</n><length>3.0</length></y>
</generator>
</mesh>
</meshes>

Fichiers et lecteurs de maillage

Lorsque le maillage est lu à partir d'un fichier (élément <filename>), le service de lecture de maillage est automatiquement détecté à partir de l'extension du fichier. Les lecteurs suivants sont fournis par Arcane (la liste des lecteurs disponibles dépend des options de compilation) :

Extension(s)ServiceDescription
vtkVtkLegacyCaseMeshReaderFormat VTK (structuré) hérité.
vtk / vtuVtkPolyhedralCaseMeshReaderFormat VTK/VTU avec prise en charge des mailles polyédriques. Options : print-mesh-infos (bool, par défaut false) et print-debug-infos (bool, par défaut false).
vtuVtuCaseMeshReaderFormat VTK (VTU) XML.
mshMshCaseMeshReaderFormat Gmsh.
medMEDCaseMeshReaderFormat MED (nécessite la prise en charge HDF5).
unf / mli / mli2 / ice / uns / unvLimaCaseMeshReaderFormats Lima (nécessite la prise en charge Lima).

La détection automatique peut être évitée et le lecteur configuré avec l'élément <specific-reader>. Par exemple :

<meshes>
<mesh>
<filename>faultx4_3x3x2.vtk</filename>
<specific-reader name="VtkPolyhedralCaseMeshReader">
<print-mesh-infos>true</print-mesh-infos>
</specific-reader>
</mesh>
</meshes>

Spécification héritée des maillages (balise <mesh> ou <maillage>)

Avertissement
Cette méthode est obsolète : elle est conservée uniquement pour la compatibilité avec les codes existants. Les nouveaux codes et les nouveaux utilisateurs doivent utiliser la méthode basée sur les services de maillage (voir Spécification des maillages avec les services (balise <meshes>)).

Avec cette méthode, les informations de maillage sont spécifiées avec un ou plusieurs éléments <mesh> (ou <maillage> si la langue du jeu de données est le français, c'est-à-dire lorsque xml:lang="fr"). Contrairement à l'élément <meshes>, les noms des éléments et les attributs de cette méthode dépendent de la langue du jeu de données : les noms anglais et français sont donnés ci-dessous.

Le premier élément <mesh> décrit le maillage par défaut (Mesh0). Les maillages supplémentaires (c'est-à-dire les deuxième, troisième, ... éléments <mesh>) sont nommés Mesh1, Mesh2, ... ou DualMesh1, DualMesh2, ... si l'attribut dual est défini sur true.

L'exemple suivant spécifie un maillage lu à partir d'un fichier, avec un partitionnement interne :

<mesh>
<file internal-partition="true">mesh1.med</file>
</mesh>

L'élément <file> / <fichier>

L'élément <file> (ou <fichier> en français) spécifie le fichier de maillage à lire. La valeur de l'élément est le nom du fichier de maillage. Il accepte les attributs suivants :

Attribut anglaisAttribut françaisTypeValeur par défautDescription
formatformatstringnoneForce le format du fichier de maillage (c'est-à-dire son extension, par exemple mli). Par défaut, le format est déduit de l'extension du nom du fichier.
internal-partitioninternal-partitionboolfalseSi true, le maillage est partitionné en interne par Arcane : un seul processus lit le fichier de maillage et le maillage est ensuite distribué entre les processus. Si false ou absent, chaque processus lit sa propre partie à partir de fichiers pré-partitionnés nommés CPU%05d.&lt;ext&gt;.
partitionerpartitionerstringnoneNom du service de partitionnement à utiliser lorsque internal-partition est true.
uniqueuniqueboolfalseSi true, un fichier de maillage unique est utilisé même en parallèle (pas de fichiers CPU%05d.&lt;ext&gt;).
cut_Ncut_NstringnoneRépertoire contenant les fichiers de maillage pré-partitionnés pour N sous-domaines, où N est le nombre de sous-domaines (par exemple, cut_4 pour 4 sous-domaines).

L'élément <meshgenerator>

L'élément <meshgenerator> (le nom est le même en anglais et en français) permet de générer un maillage sans fichier de maillage. Il contient un et un seul des éléments suivants :

<cartesian> — Générateur de maillage cartésien. La dimension du maillage est déduite de la présence des éléments <lz> (2D s'ils sont absents, 3D s'ils sont présents). Il accepte les éléments suivants :

ÉlémentTypeDescription
originereal3Origine du maillage (seules les deux premières composantes sont utilisées pour un maillage 2D).
nsdinteger[]Nombre de sous-domaines dans chaque direction. Le nombre de valeurs doit être égal à la dimension du maillage.
lxrealLongueur d'un bloc en X. Cet élément peut être répété pour décrire plusieurs blocs consécutifs. Il possède un attribut obligatoire nx (nombre de mailles du bloc) et un attribut optionnel prx (progression géométrique des tailles de mailles, par défaut 1.0).
lyrealIdentique à <lx> pour la direction Y (attributs ny et pry).
lzrealIdentique à <lx> pour la direction Z (attributs nz et prz). Uniquement pour les maillages 3D.
face-numbering-versionintegerVersion de l'algorithme utilisé pour calculer les identifiants uniques des faces.
edge-numbering-versionintegerVersion de l'algorithme utilisé pour calculer les identifiants uniques des arêtes.

<sod> — Générateur de maillage de tube de choc Sod. La dimension du maillage est déduite des éléments présents : 1D si seul <x> est spécifié, 2D si <x> et <y> sont spécifiés, 3D si <x>, <y> et <z> sont spécifiés. Il accepte l'attribut zyx (bool, par défaut false) pour générer le maillage dans l'ordre ZYX, et les éléments suivants :

ÉlémentTypeDescription
xintegerNombre de mailles en X. Attribut optionnel delta (real) : pas d'espace en X.
yintegerNombre de mailles en Y. Attribut optionnel delta (real) : pas d'espace en Y.
zintegerNombre de mailles en Z. Attribut optionnel delta (real) : pas d'espace en Z. Attribut optionnel total (bool) : si true, la valeur est le nombre total de couches pour tous les processus.
random-coefrealCoefficient de perturbation aléatoire des nœuds.

La syntaxe attendue est par exemple <meshgenerator><sod><x>nx</x><y>ny</y><z>nz</z></sod></meshgenerator>.

<simple> — Générateur de maillage simple, principalement utilisé pour les tests. Il accepte un élément :

ÉlémentTypeDescription
modeintegerType de maillage à générer (valeur entre 1 et 4).

L'élément <partitioner> / <partitionneur>

La valeur de cet élément est le nom du service de partitionnement à utiliser pour la décomposition initiale (par exemple, Metis, PTScotch, Zoltan). Si cet élément est absent, le partitionneur par défaut de Arcane est utilisé. Il accepte l'attribut suivant :

Attribut anglaisAttribut françaisTypeValeur par défautDescription
need-basic-partition-firstneed-basic-partition-firstboolfalseSi true, un partitionnement de base est effectué en premier. Ceci est utile pour les partitionneurs parallèles (par exemple, ParMetis) lorsque certaines partitions seraient autrement vides.

L'élément <tied-interfaces> / <interfaces-liees>

Cet élément spécifie les interfaces liées du maillage (par exemple, les soudures entre des parties non conformes du maillage). Il contient un ou plusieurs éléments <semi-conform> (ou <semi-conforme> en français) avec les attributs suivants :

Attribut anglaisAttribut françaisTypeValeur par défautDescription
slaveesclavestringnoneNom du groupe de faces de l'interface esclave. Cet attribut est obligatoire.
not-structurednon-structureboolfalseSi true, l'interface esclave n'est pas structurée.
planar-toleranceplanar-tolerancereal0.Tolérance pour la planéité de l'interface.
Note
Si aucune interface liée n'est spécifiée, les groupes de faces nommés SOUDURE ou SOUDURES sont automatiquement utilisés comme interfaces liées (s'ils existent dans le maillage).

L'élément <initialisation>

Cet élément permet d'initialiser les variables de maillage avec des valeurs du jeu de données. Il contient une liste d'éléments <variable>.

Note
Pour des raisons historiques, les attributs de l'élément <variable> sont toujours en français, même pour un jeu de données anglais.
AttributTypeDescription
nomstringNom de la variable à initialiser.
valeurstringValeur de la variable. La chaîne doit être convertible au type de la variable.
groupestringNom du groupe d'éléments sur lequel les valeurs sont définies.

Exemples hérités

Le premier exemple (en anglais) génère un maillage Sod et initialise les variables de maillage sur les groupes ZG et ZD :

<mesh>
<meshgenerator><sod><x>50</x><y>5</y><z>5</z></sod></meshgenerator>
<initialisation>
<variable nom="Density" valeur="1." groupe="ZG" />
<variable nom="Pressure" valeur="1." groupe="ZG" />
<variable nom="AdiabaticCst" valeur="1.4" groupe="ZG" />
<variable nom="Density" valeur="0.125" groupe="ZD" />
<variable nom="Pressure" valeur="0.1" groupe="ZD" />
<variable nom="AdiabaticCst" valeur="1.4" groupe="ZD" />
</initialisation>
</mesh>

Le deuxième exemple (en français) lit un maillage à partir d'un fichier avec des fichiers pré-partitionnés pour 4 sous-domaines situés dans le répertoire soudures_3_cut_4, et spécifie une interface liée :

<maillage utilise-unite="false">
<fichier cut_4='soudures_3_cut_4'>soudures_3.mli</fichier>
<interfaces-liees>
<semi-conforme esclave="INTERFACE1" />
</interfaces-liees>
</maillage>

Le troisième exemple (en français) génère un maillage cartésien avec un partitionneur explicite :

<maillage>
<meshgenerator>
<cartesian>
<origine>0 0 0</origine>
<nsd>1 1 1</nsd>
<lx nx="2">2.</lx>
<ly ny="1">1.</ly>
<lz nz="1">1.</lz>
</cartesian>
</meshgenerator>
<partitionneur>Titi</partitionneur>
</maillage>

Fonctions (balises <fonctions> ou <functions>)

Il est possible de définir dans le jeu de données des fonctions qui sont utilisées pour faire varier les valeurs d'une option en fonction du temps physique ou de l'itération. L'ensemble des fonctions est défini dans la balise <fonctions> si la langue est le francais ou `<functions> si la langue est l'anglais.

Note
Dans la suite du document on utilisera uniquement les termes en anglais pour améliorer la lisibilité.

Une fonction doit avoir un nom unique qui est utilisé par l'option pour la référencer. L'exemple suivante montre comment définir une fonction table-dt et l'utiliser en référence dans l'option <my-option> :

<?xml version="1.0"?>
<case codename="ArcaneTest" xml:lang="en" codeversion="1.0">
<arcane>
</arcane>
<functions>
<table name="table-dt" parameter="time" value="real" interpolation="linear">
...
</table>
</functions>
<my-module>
<my-option function="table-dt">0.01</function>
</my-module>

Les fonctions prennent un seul argument en paramètre et peuvent retourner le type attendu par l'option qui les utilise. Les deux valeurs possibles pour les paramètres sont :

  • le temps physique. Dans ce cas le type du paramètre est un reel.
  • le numéro de l'itération. Dans ce cas le type du paramètre est un entier.

Au début de chaque itération, Arcane met automatiquement à jour les options du jeu de données qui référencent une fonction (via la méthode \arcane{ICaseMng::updateOptions()}).

La balise <functions> permet de définir deux types de fonction:

  • les tables de marche qui sont spécifiées directement dans le jeu de données. Il s'agit de fonctions linéaires continues ou linéaires par morceau.
  • des fonctions externes écrite en C#. Dans ce cas il est possible de définir n'importe quel type de fonction dont la signature correspond au type attendu par l'option. Le chapître Utilisation de fonctions C# pour le jeu de données indique comment définir et utiliser ces fonctions.

Syntaxe des tables de marche

Une table de marche est une fonction linéaire continue ou linéaire par morceau définie par un ensemble de couples (X,Y). Par exemple :

<!-- Exemple en anglais -->
<functions>
<table name="table-dt" parameter="time" value="real" interpolation="linear">
<value><x>0.0</x><y>1.0e-3</y></value>
<value><x>1.0e-2</x><y>1.0e-5</y></value>
</table>
</functions>
<!-- Exemple en francais -->
<table nom='test-time-real-2' parametre='temps' valeur='reel' interpolation='lineaire'>
<valeur> <x>0.0</x> <y>3.0</y> </valeur>
<valeur> <x>4.0</x> <y>9.0</y> </valeur>
<valeur> <x>5.0</x> <y>7.</y> </valeur>
<valeur> <x>6.0</x> <y>2.0</y> </valeur>
<valeur> <x>10.0</x><y>-1.0</y> </valeur>
<valeur> <x>14.0</x><y>-3.0</y> </valeur>
</table>

Les couples (X,Y) doivent être rangés par valeur croissante de X. Si la valeur du paramètre est plus petite ou plus grande que la première ou la dernière valeur de la tablea de marche, on prend cette dernière. Dans l'exemple précédent pour la table de marche test-time-real-2, si X<0.0 on retourne 3.0 et si X>14.0 on retourne -3.0.

Les tables de marche ont les attributes suivants :

Nom AnglaisNom FrancaisTypeDescription
nomnamestringNom de la table de marche.
parameterparametrestringType du paramètre. Les valeurs possibles sont time (temps en francais) pour un paramètre qui est le temps physique ou iteration pour un paramètre qui est le numéro de l'itération courante.
valuevaleurstringType de la valeur de retour de la table de marche. Les valeurs possibles sont real, integer, real3, string ou bool (respectivement reel, entier, reel3, string et bool en francais).
interpolationinterpolationstringLes valeurs possibles sont linear ou constant (lineaire ou constant-par-morceaux en francais). Si l'interpolation est constante, la valeur retournée est celle correspondante de Y qui correspond au X immédiatement inférieur à la valeur du paramètre. Si l'interpolation est linéaire, on réalise une interpolation linéaire entre (X1,Y1) et (X2,Y2), avec X1 la valeur de X immédiatement inférieure au paramètre et X2 la valeur suivante dans la table de marche. Pour la table de marche précedente (test-time-real-2) en exemple, si X vaut 4.5 alors on retourne 9.0 si l'interpolation est constante par morceaux et 8.0 (soit Y1 + (X-X1)*(Y2-Y1)/(X2-X1) <=> 9.0 + (4.5-4.0)*(7.0-9.0)/(5.0-4.0)) si l'interpolation est linéaire.
comulcomulstringCoefficient multiplicateur pour la valeur. Cet attribut est optionnel et doit être du même type que la valeur de la fonction. S'il est présent, la valeur de la fonction est multipliée par la valeur de cet attribut (pour un Real3, la multiplication est faite composante par composante)
deltat-coefdeltat-coefrealCoefficient multiplicateur pour le temps physique. Cet attribut est optionnel et est utilisé pour multiplier la valeur du pas de temps courant (voir \arcane{ICaseMng::updateOptions()}).
