The Mesh

The IMesh interface (defined in arcane/core/IMesh.h) is the interface of a mesh. A mesh is composed of a set of entities (Item), such as nodes (Node), edges (Edge), faces (Face), or cells (Cell). It is also possible to associate other kinds of entities, such as particles (Particle) or degrees of freedom (DoF).

Entities of the same kind are managed in a family (IItemFamily, see The Item Family). A mesh has a dimension, retrievable via IMesh::dimension(), which can be 1, 2, or 3. The dimension corresponds to the dimension of the cell elements.

When an Arcane application runs in parallel, the mesh is partitioned into several subdomains: each subdomain owns a portion of the mesh, completed by one or more layers of ghost entities owned by the other subdomains (see Handling parallelism in Arcane). The IMesh instance of a subdomain represents this local view of the mesh.

Primary and Secondary Meshes

There are two types of meshes implementing IMesh:

  • primary meshes, which also implement the IPrimaryMesh interface and which can be created dynamically or by reading a file. A primary mesh is created either when reading the data set, or by programming, by calling one of the IMainFactory::createMesh() methods. It is not possible to delete a primary mesh.
  • secondary meshes (also called sub-meshes), which depend on a primary mesh and represent a subset of it. A sub-mesh is attached to its parent via IMesh::defineParentForBuild(), and the parent/child relationship can be retrieved with IMesh::parentMesh() / IMesh::parentGroup() and IMesh::childMeshes().

IMesh::isPrimaryMesh() indicates if the instance is a primary mesh, and IMesh::toPrimaryMesh() returns the instance in the form of an IPrimaryMesh (throwing an exception if it is not one).

Getting a Mesh

The default mesh of a subdomain is retrieved with ISubDomain::defaultMesh(). It is generally preferable to use ISubDomain::defaultMeshHandle(), which returns a MeshHandle: a stable reference to the mesh that always exists, even if the associated mesh has not yet been created.

A subdomain can have several meshes. They are managed by the mesh manager, retrieved with ISubDomain::meshMng(), and the list of meshes is available via ISubDomain::meshes().

Mesh Entities and Families

For any mesh, there is exactly one family of nodes, one of edges, one of faces, and one of cells. These entities are called base mesh entities and the associated families are the base mesh families:

  • IMesh::nodeFamily(), IMesh::edgeFamily(), IMesh::faceFamily(), IMesh::cellFamily()

Depending on the implementation and the requested connectivity, a family may not contain any element. For example, by default in 3D, edges are not created.

It is also possible to create additional families for other entity kinds or named families:

IMesh* mesh = subDomain()->defaultMesh();
IItemFamily* particles = mesh->createItemFamily(IK_Particle, "MyParticles");
IItemFamily* family = mesh->findItemFamily(IK_Particle, "MyParticles");

The number of entities of each base kind is given by IMesh::nbNode(), IMesh::nbEdge(), IMesh::nbFace(), and IMesh::nbCell() (or IMesh::nbItem() for a generic kind).

The cell types follow the numbering convention of the VTK library (see Cell types).

Groups of Entities

An entity group (ItemGroup) contains a set of entities of a given family. Groups are the main way to iterate over the entities of a mesh. The IMesh interface provides the following built-in groups:

Group Description
IMesh::allNodes() / IMesh::allEdges() / IMesh::allFaces() / IMesh::allCells() All entities of the subdomain (including ghosts)
IMesh::ownNodes() / IMesh::ownEdges() / IMesh::ownFaces() / IMesh::ownCells() Entities owned by the subdomain
IMesh::outerFaces() Faces on the boundary of the subdomain

Other groups can be created and searched by name:

  • IMesh::groups(): the collection of all groups,
  • IMesh::findGroup(): the group named name, or a null group if none exists,
  • IMesh::destroyGroups(): destroys all groups.

Groups are the recommended way to retain a set of entities across mesh modifications: entity instances (Item) and their local identifiers may become invalid after a mesh update, while groups are updated automatically.

Modifying a Mesh

A mesh can be dynamic, i.e. able to evolve during the computation (IMesh::isDynamic()). Modifications are performed through the IMeshModifier interface, retrieved with IMesh::modifier():

IMesh* mesh = subDomain()->defaultMesh();
IMeshModifier* mod = mesh->modifier();
mod->addCells(0, cells_infos, true); // add cells described by unique numbers
mod->removeCells(cells_to_remove); // remove cells (by local identifier)
mod->endUpdate(); // collective: finalize the modification

Once the modifications are made, IMeshModifier::endUpdate() must be called. This method is collective and, depending on the mesh properties (see below), sorts and/or compacts the entities, updates the groups, resizes the variables, and updates the ghost layers.

Warning
Sorting or compacting the entities modifies the Item::localId() of all geometric entities of the mesh. Therefore, you must not retain an entity via the Item class (or a derived class) or its local identifier after calling this method. Use groups (or unique numbers) instead.

Creating a Primary Mesh by Programming

To create an empty 2D mesh named "Mesh2":

// sd is the current subdomain.
ISubDomain* sd = ...;
IParallelMng* pm = sd->parallelMng();
IMainFactory* mf = sd->application()->mainFactory();
IPrimaryMesh* new_mesh = mf->createMesh(sd, pm, "Mesh2");
new_mesh->setDimension(2);
new_mesh->allocateCells(0, Int64ConstArrayView(), false);
new_mesh->endAllocate();

The created mesh exists across all ranks of the IParallelMng passed as an argument. To create a mesh on a single processor, you can use IParallelMng::sequentialParallelMng(). The mesh dimension must be set with IPrimaryMesh::setDimension() before allocating cells.

It is also possible to read a mesh directly from a file using the MeshReaderMng class. The reader used is selected based on the extension of the file name, and the mesh is created by the call:

// sd is the current subdomain.
MeshReaderMng mrm(sd);
IMesh* mesh = mrm.readMesh("Mesh2", "sod.vtk");
// To read the mesh on a specific group of subdomains:
IMesh* mesh3 = mrm.readMesh("Mesh3", "sod.vtk", sd->parallelMng());

Mesh Properties

A mesh has properties, accessible via IMesh::properties():

  • "sort" (boolean, true by default): entities must be sorted by increasing unique number after a mesh modification. This ensures that operations always happen in the same parallel order, regardless of the number of subdomains.
  • "compact" (boolean, true by default): entities must be compacted after a mesh modification, so that there are no gaps in the local numbering (the local identifiers are renumbered from 0 to the number of entities). Compacting is a costly operation because it requires updating all variables.
  • "dump" (boolean, true by default): the mesh must be saved during a checkpoint.
  • "edges" (boolean, false by default): edges must be created in a 3D mesh.
  • "sort-subitemitem-group" (boolean, false by default): whether dynamically created groups of connected entities (e.g. allCells().nodes()) are sorted. Must be set during mesh creation.

Load Balancing and Redistribution

When load balancing redistributes the mesh between processors, the IPrimaryMesh::itemsNewOwner() variable of the primary mesh contains, for each entity, the number of its new owning subdomain. These variables must be synchronized, and the redistribution is then performed with IPrimaryMesh::exchangeItems():

  • the subdomain gives the cells that now belong to other subdomains to them, and receives the new cells (and the same for nodes, edges, and faces),
  • the values of the variables and of the entity groups are exchanged,
  • the method triggers an implicit call to IMeshModifier::endUpdate().

After the call, you may need to execute the mesh change entry points (ITimeLoopMng::execOnMeshChangedEntryPoints()).

Other Features

  • AMR: if adaptive mesh refinement is activated (IMesh::isAmrActivated()), the mesh provides the groups of active cells (IMesh::allActiveCells(), IMesh::ownActiveCells()) and of cells at a given level (IMesh::allLevelCells()). See AMR for Cartesian Meshes.
  • Ghost layers: IMesh::ghostLayerMng() gives access to the ghost layer manager and IMesh::updateGhostLayers() rebuilds the ghost layers.
  • Connectivity: IMesh::connectivity() returns the connectivity descriptor (a VariableScalarInteger using the Arcane connectivity numbering, see Entity Connectivity Management), and IMesh::indexedConnectivityMng() the indexed incremental connectivity manager.
  • Unique IDs: IMesh::meshUniqueIdMng() manages the unique numbering of the entities.
  • Semi-conforming interfaces: IMesh::computeTiedInterfaces(), IMesh::hasTiedInterface(), and IMesh::tiedInterfaces() manage the tied interfaces between non-conforming sub-meshes.
  • Partitioning constraints: IMesh::partitionConstraintMng() manages the constraints on the mesh partitioning.
  • Utilities and checks: IMesh::utilities() gives access to mesh utility functions (IMeshUtilities), IMesh::checker() to the mesh validity checker, IMesh::checkValidMesh() (local) and IMesh::checkValidMeshFull() (collective, across all subdomains) to validate the internal structures.
  • Events: IMesh::eventObservable() provides observables for mesh events.
  • User data: IMesh::userDataList() allows associating user data with the mesh.
  • Family network: IMesh::itemFamilyNetwork() gives access to the graph of the connected families.

Key Points

  • IMesh is the local (per-subdomain) view of a mesh: it contains the entities owned by the subdomain plus the ghost entities.
  • Use ISubDomain::defaultMeshHandle() (a MeshHandle) rather than ISubDomain::defaultMesh() when the mesh may not have been created yet.
  • Primary meshes are created by the data set or via IMainFactory::createMesh(); sub-meshes are subsets of a primary mesh.
  • Modify the mesh only through IMesh::modifier(), and always call IMeshModifier::endUpdate() after a modification.
  • Do not retain Item instances or Item::localId() values across an IMeshModifier::endUpdate(): use groups or unique numbers.
